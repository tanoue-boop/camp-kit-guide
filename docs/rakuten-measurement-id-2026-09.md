## 2. `rafcid` / `m` の有無の由来（git 追跡・API実測）

### 由来

| 時点 | `hgc/5318aefd…`（pc= のみ） | `hgc/g00…`（API形式） | 素URL `item.rakuten.co.jp` |
|---|---|---|---|
| `d26d056^`（修復前） | 94 | 948 | 394（+ search 13） |
| `d26d056`（楽天リンク修復 407件） | 501 | 948 | 0 |
| `79fd160`（Amazon一本足10記事に42カード追加） | 543 | 948 | 0 |
| `HEAD`（`12aa57e`） | **543** | **948** | 0 |

- **pc= のみ 543本 = 94（`d26d056` 以前から存在：ASP記事のふるさと納税CTA・`331aaf2` のFAIL5記事修復など）＋ 407（`d26d056` の一括変換）＋ 42（`79fd160`）**。仮説「543本は `d26d056` の修復分」は**部分的に正しい**（407本がそれ。残り136本は別コミット）。
- **API形式 948本** は楽天ウェブサービス商品検索APIに `affiliateId` を渡したときの `affiliateUrl` をそのまま貼ったもの。本タスクで同APIを1回呼び、返り値が `https://hb.afl.rakuten.co.jp/hgc/g00t9gon.20yylc22.g00t9gon.20yym6af/?pc=…&m=http%3A%2F%2Fm.rakuten.co.jp%2F…&rafcid=wsc_i_is_<RAKUTEN_APP_ID>` 形式であることを確認した。4分割IDの第1・第3セグメントはショップ、第2・第4セグメント（`20yyl…`/`20yym…`）はアフィリエイトID由来のハッシュで、ショップごとに異なる。
- `scripts/rakuten-search.mjs`（2026-09-20 追加）は `affiliateId` をAPIに渡さず、`itemUrl` を `hgc/<AFF_ID>/?pc=` に包む方式のため、以後の新規リンクは pc= のみ形式になる。

### pc= のみ形式は報酬が発生する形式か

**成立していると判断する（構造的根拠あり・成果実績での確認は未）。**

1. G3 ガイドラインに掲載されている公式発行リンクの例も `https://hb.afl.rakuten.co.jp/hgc/<16進4分割ID>/?pc=<商品URL>&m=…&scid=…&link_type=text&ut=…` であり、`hgc/<AFF_ID>/?pc=` が公式リンクの骨格。`m=`（モバイルURL）・`scid`・`link_type`・`ut` は付加情報。
2. `docs/scheduled-task-spec.md` の運用ルール（「記事に載せるアフィリURLは hb.afl 形式に統一」）が採用している形式そのもの。
3. リダイレクト実測（購入なし・各1リクエスト）: pc= のみ形式は `hgc/…` → 302 `ichiba/<AFF_ID>/?pc=…&afct=g_1` → 302 `pt.afl.rakuten.co.jp/c/5318aefd.9830f687/?url=<商品URL>&ref=&ut=&link_type=&afct=g_1` と、API形式（`pt.afl.rakuten.co.jp/c/g00rr09n.20yylffa/?url=…&rafcid=…`）と**同じトラッキング経路**を通る。アフィリエイトIDの先頭2セグメントがトラッキングURLに載る。
4. 一方で「この形式で成果が計上された実績」はまだ確認できていない（`d26d056` の効果測定は `docs/seo-change-log.md` に「2〜3週間後に管理画面で確認」と記載済み）。**#4 の積み残しとは判断しないが、次回の管理画面確認（Cowork）で pc= のみ形式のクリックが期間別レポートに乗っていることを必ず見ること。**

### 3-3. 既存リンクの移行方針とロールバック

- **移行単位は記事1本＝1コミット**（`git add content/posts/<slug>.mdx` の個別指定）。`node scripts/count-hb-params.mjs` で「総数が変わらない・broken 0」を各コミット前に確認する。
- 再発行リンクが `/hgc/` ではなく `/ichiba/` 形式で出る可能性がある（リダイレクト実測で `hgc → ichiba` に転送されているため）。その場合は `count-hb-params.mjs` の `OK_RE` と `scripts/verify-deploy.cjs`・`count-rakuten-links.mjs` の判定を先に更新してから貼り替える。
- **ロールバック**: 記事単位の `git revert`（1コミット=1記事なので他記事に波及しない）。計測ID付きリンクを外しても旧リンク（pc= のみ／API形式）は引き続き有効なので、計測が取れないだけで報酬は失わない。
- 楽天側の計測ID登録は削除せず残す（削除するとレポートの過去分の見え方が変わる可能性があるため。確認できるまで残す）。
